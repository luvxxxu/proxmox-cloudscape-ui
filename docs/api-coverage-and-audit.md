## 구현 형태와 범위

| 영역 | 전용 화면 | 추가 기능에 접근하는 방법 |
|---|---|---|
| 사용자·그룹·역할·ACL | 조회·생성·편집·삭제, 실제 그룹 보존, 선택형 권한, 유효 권한 | 전체 API에서 추가 권한 조회·고급 매개변수 |
| 사용자 보안 | 비밀번호, 토큰 생성·수정·삭제·비밀 재생성, TOTP·YubiKey·WebAuthn/패스키 등록·복구 코드·잠금 해제 | 서버 버전이 허용하는 전체 TFA API |
| 인증 영역 | PVE/PAM, LDAP/AD/OpenID 설정, 기존 상세 설정·digest 보존 | LDAP 동기화 등 고급 작업의 API 매개변수 폼 |
| 로그인 | 비밀번호, OTP/복구 코드, WebAuthn, OIDC, 세션 갱신 | 구형 U2F는 기본 Proxmox UI 필요 |
| VM·LXC | 목록·상세·생성·전원·클론·마이그레이션·콘솔·스냅샷·백업·설정 | guest agent, 고급 장치·디스크 API, 추가 매개변수 |
| 노드 | 상태·셸·서비스·패키지·인증서·시간·DNS·디스크·구독·클러스터 가입 | 하드웨어 매핑·고급 노드 API |
| 백업·스토리지 | 스토리지 설정, 파일 업로드, 백업·복원 | 백업 예약(`/cluster/backup`), 고급 저장소·파일 작업 |
| 네트워크·방화벽 | 인터페이스·규칙·별칭·IPSet·보안 그룹·옵션 | SDN·fabric·zone·VNet·subnet 고급 폼 |
| HA·복제 | 기존 HA 그룹·리소스, 실제 런타임 상태, 복제 예약·실행 | 새로운 HA affinity rules는 전체 API 폼 |
| Ceph·알림·리소스 매핑 | 개별 전용 화면 없음 | 전체 API에서 해당 경로 검색·매개변수 입력·변경 검토·실행 |

**전체 API 관리**는 단순 문서 링크가 아니라 실행 가능한 공통 폼입니다. 필수·선택 매개변수, enum, boolean, 숫자 범위, 반복 장치 이름, 배열과 조건부 매개변수를 처리합니다. 서버 오류를 필드와 요약에 표시하며, 변경은 요청 내용을 검토한 뒤 실행합니다. DELETE는 대상 경로 재입력이 필요합니다. 3개의 `vncwebsocket` GET은 실시간 프로토콜이므로 VM/LXC 콘솔 또는 노드 셸을 이용하도록 안내합니다.

일부 복잡한 설정은 공식 Proxmox property-string 형식이나 추가 매개변수 입력이 필요합니다. 모든 기능을 별도 마법사로 재구현한 것은 아닙니다. JSON/스키마 검증은 서버의 플러그인별 의미 검증을 대체하지 않습니다.

## 수정한 주요 결함

### 인증·중계·운영

- 비로그인 요청이 서버의 API 토큰을 상속하던 경로 제거. 모든 관리 요청에 로그인 티켓 필요.
- 편집 가능한 JSON 쿠키를 AES-GCM 인증 암호화·만료 검증 쿠키로 교체. HTTP와 WebSocket에서 같은 검증 사용.
- 글로벌 TLS 검증 해제 제거. Proxmox CA를 Node 시작 시 등록하고 인증서 이름 검증 유지.
- 사용자와 서버 origin 검사, CSRF, 인증 시도 제한, OIDC 상태 쿠키 바인딩, 실제 티켓 갱신.
- 변경 요청의 네트워크/5xx 자동 재시도 제거. 실패 응답만으로 같은 생성·삭제가 반복되지 않음.
- 업로드·다운로드 중계 스트리밍, 종료·취소·시간 제한, WebSocket origin·백프레셔·연결 수 관리.
- Next.js `proxy.ts`와 동적 CSP nonce, 보안 헤더, 공개 프로세스 health, 정상 종료 처리.
- 로그인 실패·세션 검증 장애·로그아웃 실패를 구분해 표시. 빈 화면 또는 허위 로그아웃 방지. 로그아웃 전에 진행 중인 갱신 요청을 취소하고 종료를 기다리며, Web Locks를 지원하는 브라우저에서는 탭 사이의 갱신·로그아웃도 직렬화해 지운 쿠키가 늦은 갱신 응답으로 복원되는 경합을 방지.
- Docker와 systemd 설치의 실행 코드를 root 소유로 유지하고 앱 캐시만 서비스 사용자에게 쓰기 허용. 설정 예제의 세션 비밀은 비워 두어 미설정 상태로 시작하지 못하게 함. Nginx 인증·콘솔·API 경로는 요청 URL이 오류 로그에 남는 경로도 차단. 로그인·OIDC 본문은 16 KiB로 제한하고 디스크 버퍼링을 끔. Compose는 CA 파일이 없으면 자동으로 디렉터리를 만들지 않고 시작을 거부.

### 사용자·역할

- 사용자 목록을 `full=1`로 가져와 편집 시 원래 그룹과 토큰을 잃지 않도록 수정.
- 사용자 프로필 PUT에 지원하지 않는 password를 보내던 문제를 별도 비밀번호 API로 수정.
- LDAP/AD 영역의 빈 포트, SSL 모드, TFA `none` 직렬화 오류 수정. 영역 상세 설정·digest를 읽고 기존 설정을 보존.
- 사용자·역할·ACL 생성 선택지, 필드 오류, 부분 403 표시, root 계정 삭제 보호, 만료 날짜 검증.
- API 토큰 비밀과 복구 코드는 1회 표시하고 숨김·정리. 토큰 만료 해제는 `expire=0` 사용. 토큰 수정의 정상 `data: null` 응답도 처리.
- WebAuthn/패스키 등록은 공식 [AddWebauthn.js](https://github.com/proxmox/proxmox-widget-toolkit/blob/master/src/window/AddWebauthn.js)의 2단계 API 교환을 따름. 브라우저 등록 취소 시 완료 요청을 보내지 않고 비밀번호 입력 상태를 정리. 실제 RP ID·origin 구성과 보안 키 장치는 설치 환경에서 별도 확인 필요.
- 권한 API의 값 0은 “권한 없음”이 아니라 전파 여부임을 반영. 미확인 권한을 허용으로 취급하지 않음.

### 리소스·사용성

- HA 그룹 데이터를 새로운 HA 규칙 API로 보내던 경로 오류 수정. 기존 그룹은 `/cluster/ha/groups`로 관리하고 새 affinity 규칙은 전체 API에서 관리하도록 안내. 설정 상태와 실제 서비스 상태를 구분해 표시.
- 복제 작업의 필수 `id` 누락을 수정하고 사용 중인 작업 번호를 피해서 생성. 편집 시 변경 불가 필드를 제외하고 비운 선택값을 삭제. 노드별 실제 복제 상태 조회와 즉시 실행 추가.
- PBS의 `backup/vm/...`, `backup/ct/...` 경로 인식, LXC 복원의 `ostemplate`/`restore=1`, VMID 범위 검증.
- 활성 상태가 0인 스토리지를 생성·복제·백업·복원 선택지에서 제외. 업로드 파일을 Proxmox가 요구하는 multipart `filename` 필드로 전송하고 Cloudscape FileUpload로 선택·제거 상태 표시.
- 클러스터 참가 정보를 로컬 `link0`로 보내던 문제 수정. [공식 Proxmox 참가 화면](https://github.com/proxmox/pve-manager/blob/master/www/manager6/dc/ClusterEdit.js)의 Base64 JSON 참가 정보에서 피어 주소와 인증서 지문을 읽고, 참가할 노드의 링크 0~7 주소는 별도로 입력. 직접 입력 모드, 필요한 링크·SHA-256 지문 검증, 비밀번호 공백 보존, 참가 오류의 모달 내 표시 추가.
- 노드 구독 활성화 요청을 PUT으로 수정. Wake-on-LAN은 노드별 성공·실패와 실제 대상 이름을 표시.
- 풀에서 VM을 뺄 때 `qemu/100` 대신 숫자 VMID를 전달.
- 네트워크 편집 시 실제 NIC·OVS 유형을 bridge로 바꾸던 문제와 CIDR 중복 결합 수정. IPv4 주소·접두사 범위·연속된 서브넷 마스크 검증 추가.
- 방화벽 기본 옵션값과 잘못된 smurf 옵션 이름 수정. 지운 규칙 제약과 선택 설정은 API의 `delete` 매개변수로 제거해 이전 값이 남지 않도록 처리.
- VM guest agent·메모리의 복합 설정값을 읽고 다른 하위 옵션을 보존해 편집. Cloud-Init SSH 키 인코딩과 빈 선택값 삭제, 생성 시 CPU·메모리·디스크·balloon 범위 검증 수정. BIOS와 EFI 디스크 선택의 동기화 수정.
- LXC 마이그레이션에 지원하지 않는 live/online 대신 `restart`를 사용하고 서비스 중단을 안내.
- 정상 종료와 강제 중지를 구분하고 강제 중지에는 대상 VMID 재입력을 요구. 일괄 전원·삭제 작업의 일부 성공을 보존해 개별 실패와 함께 표시. 템플릿 실행 차단과 삭제 진행 중 대상 변경 방지.
- 노드 디스크 초기화·데이터 지우기는 장치 경로를 재입력한 경우에만 실행. 요청 진행 중 확인창 닫기와 중복 실행을 막고 실패 이유를 확인창 안에 표시.
- UPID 접수를 작업 완료로 표시하던 문제 수정. 실제 종료 상태 추적, 같은 설명의 다른 작업 구분, 장애 시 상태 미확인 표시, 완료 후 목록 갱신.
- VM·CT 목록을 클러스터 자원 조회로 구성해 오프라인 노드의 게스트도 표시. 노드의 결측 CPU·가동 시간은 `NaN` 대신 미확인으로 표시하고 크기 단위는 IEC 단위로 통일.
- VM·CT·노드 상세 조회에서 이전 요청 취소와 대상 확인으로 늦은 응답이 다른 자원 화면을 덮어쓰는 문제 수정. 방화벽·하드웨어의 부가 조회 오류를 구분해 성공한 다른 응답이 권한 오류를 지우거나 자동 재요청이 반복되는 문제 방지.
- Proxmox syslog의 `t` 필드를 시간으로 오해해 로그 내용을 숨기던 문제 수정. 노드 전환 후 이전 로그 응답을 무시하고, 작업·백업·스토리지·네트워크의 일부 조회 실패가 다른 노드의 정상 결과를 숨기지 않도록 처리.
- 백업·복원·업로드의 선택값은 현재 가능한 옵션에서 계산해 노드·내용 유형 변경 후 무효한 선택이 남지 않도록 수정. Flashbar의 동작하지 않던 닫기 버튼과 치환되지 않던 대상 이름 수정.
- 대시보드의 요청 경합·취소·갱신 주기·CPU 가중 집계·오프라인/결측값 처리 개선.
- 한국어 Cloudscape 기본 문구·접근성 라벨 반영, 저장 설정 검증, 저장 공간 부족 시 메모리 내 설정 유지.
- 오래된 의존성 갱신. 사용하지 않는 SVG 빌드 의존성 제거 및 보안 수정된 PostCSS로 고정.

## Cloudscape 준수 방법

[공식 llms.txt](https://cloudscape.design/llms.txt)를 출발점으로 Form, FormField, Table, Modal, 검증, 국제화 문서를 확인했습니다. 기존 Cloudscape 컴포넌트를 유지하고 새 외부 스타일 라이브러리를 추가하지 않았습니다.

- 폼은 라벨·제약·필드 오류·서버 오류·제출 상태를 제공합니다.
- 테이블은 고유 키, 검색, 페이지 이동을 사용합니다.
- 수정·삭제는 Cloudscape Modal에서 실제 대상을 확인합니다.
- 전체 API 폼은 작성 중 이탈과 진행 중 요청 유실을 방지합니다.
- 결과·장기 작업은 Alert/Flashbar를 사용하고 민감한 응답은 기본적으로 가립니다.
- Cloudscape의 공식 컴포넌트와 DOM 테스트 도구를 사용해 주요 흐름을 검사했습니다.

브라우저 테스트는 Proxmox의 실제 작업 엔진 대신 메모리 내 API 테스트 서버를 사용합니다. 최종 실행에서 테스트 API 요청 78건이 발생했고 브라우저 오류와 모바일 페이지의 가로 넘침은 없었습니다. 앱→테스트 API의 CA 검증을 유지했습니다. 화면 이미지는 `test-results/`에 저장됩니다. Cloudscape 테스트 도구 패키지의 소스맵 경고가 있으나 테스트 실패는 없으며, 빈 문자열 조건부 렌더링에서 발생하던 React 키 경고는 수정하고 재발 검증을 추가했습니다.

배포 구성은 `scripts/check-deployment.sh`로 반복 검사할 수 있습니다. 이 검사는 격리된 컨테이너에서 실행하며 호스트 서비스를 시작하지 않습니다. Nginx 1.31.2의 TLS 구성, 실제 과대 인증 요청의 413 거부, Compose 구성, Debian 12/Node 24 컨테이너의 shellcheck·systemd unit 검증과 설치 스크립트 2회 실행을 통과했습니다. 설치 후 코드 읽기/쓰기 권한, 캐시 쓰기 권한, 환경 파일 0600 모드, current/previous 롤백 링크를 확인했습니다. 실제 Debian 13 게스트의 systemd 부팅까지 검증했다는 의미는 아닙니다. CI에도 이 검사를 연결했으며 GitHub에서 실행된 CI 결과는 이번 로컬 검증에 포함하지 않습니다.

실제 설정된 Proxmox 서버에 대한 인증서 검증은 `UNABLE_TO_VERIFY_LEAF_SIGNATURE`로 실패했습니다. 이를 우회하지 않았습니다. 현재 작업에서는 실제 클러스터의 사용자·역할·VM·네트워크·스토리지를 변경하지 않았습니다.

따라서 실제 클러스터의 계정 정책, PAM/LDAP/IdP 설정, 저장소 플러그인, Ceph/SDN/HA 토폴로지, 실제 콘솔과 장기 부하 검증은 설치 환경에서 남아 있습니다. 제공된 스크립트와 브라우저 테스트의 성공은 그 범위 안의 증거입니다. 운영 승인 전 검증 목록은 [설치 안내 11절](installation.ko.md#11-운영-승인-전에-실제-클러스터에서-확인할-항목)에 있습니다.

## LXC 설치 추가 검증

2026-09-09에 LXC 설치기와 소스 패키징을 추가한 뒤 수행한 검사입니다. 위의 최초 검사 이후 추가된 테스트를 포함해 **32개 파일, 211개 테스트**를 Debian 12와 13에서 각각 통과했습니다.

| 검사 | 결과와 범위 |
|---|---|
| 새 설치 | Linux amd64 Debian 12·13에서 실제 패키지 설치, SHA-256을 확인한 Node.js 24.20.0·Bun 1.3.12 다운로드, 비특권 빌드, 린트·타입 검사·211개 테스트·의존성 감사·프로덕션 빌드 통과 |
| HTTPS 실행 | 각 배포판의 Nginx 1.22.1·1.26.3에서 앱 상태 응답, CA 검증을 유지한 HTTPS 접속, 미인증 API의 401 거부 확인 |
| 파일 권한 | 앱의 실행 코드 쓰기 금지, 캐시 쓰기 허용, 환경 파일과 UI 개인 키의 0600 권한 확인 |
| 업데이트와 실패 복구 | 재설치 후 환경 파일·세션 비밀 보존, current/previous 링크 확인. 세 번째 설치에서 앱 시작 실패를 주입한 뒤 이전 앱·설정·링크와 HTTPS 상태 복구 확인 |
| 소스 패키지 | 실제 수정·새 소스 포함, 비밀 파일·빌드 결과·심볼릭 링크 배제. macOS BSD tar·Linux GNU tar에서 패키징 회귀 테스트 5개 통과, macOS 생성 아카이브의 Debian 추출 메타데이터 경고 0건 |
| 설치기 검사 | ShellCheck·Bash 구문 검사와 서비스 사전 검사·별도 빌드 경로·심볼릭 링크 경합·권한·재설치 배포 회귀 검사 통과 |

처음에는 amd64 에뮬레이션 환경에서 많은 Cloudscape 화면 테스트가 동시에 실행되며 5초 제한을 넘겼습니다. 테스트의 단언이나 제한 시간을 바꾸지 않고 `maxWorkers: 2`로 동시 실행 수를 제한한 뒤 두 배포판의 전체 검사가 통과했습니다.

Proxmox 연결 사전 검사는 로그인 없이 허용되는 `/api2/json/access/domains`를 사용합니다. `/version`은 인증이 필요하므로 사용하지 않습니다. [공식 인증 처리 코드](https://github.com/proxmox/pve-manager/blob/master/PVE/HTTPServer.pm#L63-L87)를 대조했습니다. Nginx 재시작·인증서 적용 지연에는 TLS 검증을 유지하는 제한된 재시도를 적용했습니다.

`scripts/check-lxc-install.sh`는 일회용 Docker 컨테이너에서 실제 앱과 Nginx를 실행하지만 **LXC 감지와 systemd 실행 명령은 테스트용으로 대체합니다.** 초기 설치는 모든 검사와 빌드를 실행하며, 이후 업데이트·실패 시나리오만 검증된 빌드를 재사용합니다. 실제 설치기에는 검사·빌드 생략 옵션이 없습니다. 실제 Proxmox LXC의 부팅·커널·AppArmor·systemd 격리, 실제 계정 로그인과 리소스 작업을 검증한 결과는 아닙니다. 실제 설치기는 게스트 안에서 서비스 격리 사전 검사를 실행합니다. CI는 Debian 12·13 매트릭스로 구성했으며 원격 CI 실행 결과는 포함하지 않습니다.

설치 절차와 실행 위치별 명령은 [LXC 설치 안내](installation-lxc.ko.md)에 있습니다.
