# 공개 릴리스 설치와 자동 업데이트

사용자는 GitHub 계정이나 PAT 없이 설치하고 업데이트합니다. GitHub Actions의 임시 `GITHUB_TOKEN`은 제작자가 릴리스를 게시할 때 CI 내부에서만 사용됩니다. 사용자 LXC에는 GitHub 자격 증명을 저장하지 않습니다.

## 사용자의 설치

[자동 설치 안내](quick-install-caddy.ko.md)의 명령을 새 Debian amd64 LXC에서 실행합니다. 설치기는 공개 안정 릴리스의 앱·Node 실행 파일과 소스를 내려받습니다. 사용자 서버에서 Bun 설치, 의존성 설치, 테스트, 빌드, `bun audit`를 실행하지 않습니다.

자동 업데이트는 설치 마지막에 기본으로 활성화됩니다. 약 15분마다(최대 2분의 분산 지연 포함) 공개 최신 안정 릴리스를 확인합니다. 직접 다운로드 URL을 사용하므로 GitHub REST API의 비인증 요청 제한을 소비하지 않습니다.

## 제작자의 배포 순서

1. 코드를 수정하고 `main`에 push합니다. 매 push/PR에서 검사가 실행됩니다. 아직 사용자 설치는 바뀌지 않습니다.
2. 배포할 때 `package.json`의 버전을 올려 커밋합니다.
3. 같은 버전의 태그를 push합니다. 예를 들어 버전이 `0.2.2`라면 다음과 같습니다.

```bash
git tag v0.2.2
git push origin main v0.2.2
```

4. Actions가 코드·타입·단위 테스트, 취약점 검사, 실제 브라우저 검사, 패키징, Debian 12/13 설치 및 복구 검사를 실행합니다.
5. 모든 필수 작업이 성공해야 공개 릴리스를 게시합니다. 먼저 비공개 draft에 파일을 모두 업로드하고 마지막에 공개하므로 사용자가 미완성 릴리스를 설치하지 않습니다.
6. 사용자 LXC가 새 안정 릴리스를 자동으로 설치합니다.

태그는 `vMAJOR.MINOR.PATCH` 형식이어야 하고 `package.json` 버전과 일치해야 합니다. 시험판 태그는 안정 채널에서 지원하지 않습니다. 공개한 버전은 덮어쓰지 않고 다음 패치 버전으로 배포합니다. 특정 버전을 되돌려야 한다면 이전 코드로 **새 버전**을 발행하세요. 자동 업데이트는 숫자가 낮은 버전으로 내려가지 않습니다.

## 설치·업데이트 검증

- 공개 manifest의 저장소·버전·커밋·플랫폼·파일 이름을 검사합니다.
- 버전이 고정된 URL에서 파일을 받고 크기와 SHA-256을 검사합니다.
- HTTPS 인증서 검증을 유지합니다. 전송 오류는 제한적으로 재시도합니다.
- 압축 해제 시 상위 디렉터리 탈출, 외부 심볼릭 링크, 장치 파일, 과도한 크기를 거부합니다.
- 앱과 같은 릴리스의 Node를 함께 전환합니다. `.env` 설정과 세션 비밀은 보존합니다.
- 새 버전이 시작되지 않거나 상태 검사에 실패하면 이전 앱·Node·서비스 설정을 복원합니다.
- 릴리스가 없거나 네트워크/해시 검사가 실패하면 실행 중인 버전을 유지합니다.

SHA-256은 다운로드 손상과 파일 불일치를 검사합니다. 배포 신뢰의 기준은 HTTPS로 연결한 공식 GitHub 저장소 및 릴리스 게시 권한입니다. 별도의 오프라인 서명을 주장하지 않습니다.

## 상태 확인

앱 LXC의 root 콘솔에서 실행합니다.

```bash
systemctl list-timers proxmox-cloudscape-update.timer
journalctl -u proxmox-cloudscape-update -n 100 --no-pager
cat /opt/proxmox-cloudscape/current/public-release.json
```

즉시 새 릴리스를 확인하려면:

```bash
systemctl start proxmox-cloudscape-update.service
```

업데이트 중에는 앱이 재시작되므로 연결이 잠시 끊길 수 있습니다. VM 콘솔을 사용 중이라면 재연결이 필요할 수 있습니다.

자동 업데이트를 중단하려면:

```bash
systemctl disable --now proxmox-cloudscape-update.timer
```

수동으로 이전 릴리스로 복구할 때도 먼저 타이머를 중단해야 다시 최신 버전으로 올라가지 않습니다. [설치·복구 안내](installation-lxc.ko.md)를 참고하세요.

기존 PAT 방식 설치에서는 새 자동 설치 명령을 다시 실행하면 새 공개 릴리스 설치와 함께 설정이 교체됩니다. 저장했던 토큰은 새 설정에 포함되지 않습니다. 더 이상 사용하지 않는 기존 토큰은 GitHub에서 폐기할 수 있습니다.

## 운영 범위

Node는 앱 릴리스에 포함되어 함께 업데이트됩니다. Debian 패키지·Nginx와 별도 Caddy의 보안 업데이트는 각 서버에서 관리해야 합니다. Caddy 설정과 인증서는 앱 업데이트가 덮어쓰지 않습니다. 업데이트 도구 자체나 서비스 격리 정책 변경은 새 설치기를 다시 실행해 반영합니다.

로컬/CI의 Debian 검사는 systemd와 LXC 감지를 대체한 격리 환경 검사입니다. 실제 Proxmox의 커널·AppArmor·네트워크·인증서와 실제 계정 로그인/콘솔은 운영 환경에서 확인해야 합니다.
